# nocx 0.7.2

0.7.1 fixed the shell for people whose startup file still sourced an old copy of the
integration. This patch fixes what that left behind: a shell that now loads twice, a
host still running the previous version's helper, and a consent question that was never
put to you.

## Updating no longer leaves you on the old background process

A new version used to attach to the background process the previous version had started,
so the window said 0.7.2 while the process running your shells was 0.7.1 — and every fix
that lives in the shell integration was silently absent.

A different version now takes over: the new window starts its own process, your running
sessions carry on where they are, and each one moves to the new version as it ends. Nothing
is stopped by hand, and nothing is lost.

## A host that still has an old integration finishes its first command again

Some hosts carried a startup line from an older nocx that sourced an old copy of the
integration. That copy is now retired when nocx publishes to the host, so the first command
in a remote pane completes instead of leaving a block that never ends.

One consequence worth knowing: an older nocx on that same host will find its own integration
inert until it is reinstalled.

## Helper mode asks before it installs

A connection set to Helper mode used to install the helper on a host without asking, if the
permission had never been recorded — and said nothing either way. It now asks the first time
you connect to a host, once per host: granted, the helper is used; refused, it is not asked
again. A dismissed question refuses the connection and the pane says the connection is
waiting for an answer.

## A pane says when its shell integration could not be copied

If nocx could not copy the shell integration to a host, the failure was written to a log and
the pane carried on as though nothing had happened. It now says so, once, and stays usable.

## A slow remote shell no longer ends up without blocks

Connecting to a host can take a while — the connection, the copy and the cleanup all happen
before your shell starts. That time used to count against the shell, so a slow host could
end up as a plain terminal with no blocks at all. The wait is now measured from two separate
moments: the connection getting ready, and the shell running without answering. A slow host
works, and a shell that truly never answers still falls back to a plain terminal.

## How to update

    brew upgrade --cask nocx

Nothing needs to be killed by hand: the new version takes over from the old one as it
starts, and your sessions keep running.

## What 0.7.2 does not include

Signed nightly builds remain in 0.8.

# nocx 0.6.1

0.6.0 shipped with a broken shell for a lot of people, and this patch is the repair. If your
zsh never integrated, if the app once opened with no window after an update, if the vault
asked you for a passphrase you had already given, or if a saved SSH profile stopped
connecting — this is that release.

## Your shell integrates again

A zsh pane started from a normal setup could fail to integrate in three separate ways, and
any one of them left the pane at "Checking this shell…" with a terminal that never became
usable. All three are fixed.

The bootstrap is no longer **typed** into your terminal. nocx used to type `. /dev/fd/3` and
read the script from a file descriptor, which meant `. /dev/fd/3` appeared in your
scrollback — twice — and that any startup file closing or draining that descriptor broke the
integration outright. The script now arrives through a transient `ZDOTDIR` whose `.zshenv`
runs before your own startup files: nothing is typed, nothing is echoed, and a startup file
touching file descriptors cannot break it.

`NOCX_SHELL_INTEGRATION` is now in the spawned shell's **environment** rather than only
inside the script. Terminal wrappers of the Fig family — and anything else guarding on that
variable — read it before your rc runs, so they stand aside as they did in 0.4 instead of
re-executing your login shell inside their own pty.

And the banner stops blaming your startup files when the prompt came back. It says what
happened: nocx's integration never answered from inside your shell.

## A replacement ends with a window

Updating used to leave you with nothing. The backend was correctly replaced — 0.4.0's
coordinator cannot serve a 0.6 window — and then no window appeared; a second launch worked.
The window is now raised before anything else is shown, and the notification about the
replaced backend waits until there is a window to put it over.

## The vault stops asking twice

The unlock prompt appears when a backend attaches, and the prompt used to be rendered inside
whatever overlay was on top — so on the first connection after an update it could be carried
off screen by the connection window closing. It also survived an answer given from anywhere
else, so a passphrase you had just typed could be asked for again, holding your keyboard,
with nothing to answer it.

Both are fixed: the prompt follows its host, and an ask ends when the vault it asks about is
already open. Answering a prompt that has just been withdrawn is now a no-op rather than an
error.

## Saved SSH profiles connect again

A profile whose key is stored in the vault failed with `ssh: unable to authenticate` on
0.6.0. An RSA key was being signed with `ssh-rsa` — the SHA-1 algorithm OpenSSH has refused
by default since 8.8 — because the helper that signs on your behalf named the key's type
instead of the algorithm the server negotiated. It now signs with `rsa-sha2-256` or
`rsa-sha2-512`, and an ed25519 key keeps working.

One refused credential is also one authentication now, not five. A failed publish used to
discard an authenticated connection and spawn a fresh authentication, which against a server
with `MaxAuthTries` or `fail2ban` could lock you out of your own host. The helper also logs
the **fingerprint** of every identity it offers — never the key — so the next report of this
kind is one line of log rather than an evening.

## The remote path stops talking to itself

Typing `ssh host` in a pane printed the handshake's own frames into your transcript —
`NOCX1 LOADER_READY`, `NOCX1 STAGE_READY`, `NOCX1 OUTCOME accepted` — in a staircase, because
a marker written as a line on the saved path is consumed by the reader that takes it. The
markers now travel inside an OSC sequence, which a terminal consumes whole.

A remote bash also no longer starts with debugging enabled. Enabling `extdebug` from a
startup file made bash load `bashdb` — printing `bash: …/bashdb-main.inc: No such file or
directory` and `warning: cannot start debugger` — and then quietly clear the flag again. It
is armed at the first prompt instead, after your startup files and before anything you type.

## Quit, and the small things

**Cmd+Q quits.** The chord was reaching the web window before the menu's key equivalent; nocx
now owns its menu and claims the chord in the window itself.

- A running command's output stays inside its block, however much it prints.
- A full-screen program's grid fills the pane again; it was fitted 48 px narrow.
- A deliberately dim separator stays dim: the readability floor ran _before_ the dim, so a
  faint grey painted brighter than the plain grey beside it.
- Scrolling with a trackpad into a program that reports mouse input is one gesture per flick,
  not dozens of wheel reports.
- A selection ends at the first key the program is sent, and when the program repaints what
  was selected — but survives the release that copies it.
- The pointer is an arrow, not an I-beam, while a program has mouse tracking on.
- Pasting an image into a program that understands one now delivers the paste.
- The input line's caret stays solid while you type, and blinks again only
  after you pause.
- The numeric keypad's Enter submits, like Return.
- A full-screen program's redraw no longer looks jerky: a redraw the program
  marks as synchronized (`DEC 2026`) is held until it is complete, and one
  complete frame is published instead of several half-drawn ones. A program
  that opens the hold and goes quiet still gets its frame after 150 ms.
- About shows the webview framework's version instead of "unknown".

## A widget-wrapping zsh plugin can no longer silently break integration

The pass's hardest finding was measured down to one plugin — `fast-syntax-highlighting`, with
`zsh-syntax-highlighting` and `zsh-autosuggestions` in the same class. The delivery they broke
is gone (`nocx-1ebrs.8`): the script now arrives through a transient `ZDOTDIR` before your own
startup files, and nocx's hooks survive the plugins' re-registration. A regression fixture now
loads all three at pinned commits, in both orders, and fails rather than skips when they are
absent (`nocx-1ebrs.27`).

## What this patch does not fix

Two findings from the same pass are open and are not in this release: a session whose
handshake never answers can still take up to ten seconds to fall back to a plain terminal
(`nocx-1ebrs.20`'s fix — the bound and the degrade — is NOT in this release), and
box-drawing characters that do not join need a procedural renderer and are a later release.

They are tracked, they are not forgotten, and this release does not claim them.

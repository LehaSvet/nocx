# nocx 0.6.0

Your terminal now paints itself. nocx stopped using xterm.js as its renderer: the backend
owns the terminal and the app draws the cells it is given, so what you see and what the
backend thinks is on screen can no longer drift apart. Alongside it, agents run in nocx's
own panes — a coordinator can start a Claude worker, answer its first dialog, and read its
report — and the app installs with one `brew` command.

## The terminal is drawn by nocx

The live screen is painted from the backend's cells rather than by a browser terminal
component. That is a change you feel rather than see: the same typing, the same paste, the
same IME, the same selection — with one source of truth for what is on the screen. Two
things follow that a renderer-of-bytes could not do: the app can tell a cell apart from a
character you typed (it knows how each was drawn), and a screen can be read back from the
backend exactly as it stands.

Selection is one model across the whole pane now, live output and finished blocks alike.
Dragging over the live grid selects and keeps the selection when you let go — including
inside a full-screen program like Claude, which used to swallow it. Double-clicking a word
in a command's output selects that word and copies it, as it does in any terminal.

## Agents run in nocx panes

A coordinator can start a worker in its own pane with `workers.spawn`, answer the folder
trust question that Claude asks the first time, and receive the worker's report through
nocx's own tools — the worker arrives with its task and with nocx's rules, without you
typing anything into its input box. `workers.close` closes the worker and its tab.

This is the orchestration work landing, not the whole of herdr replaced. The 0.6 milestone
was frozen on 2026-10-19 before its working-day outcome could be finished: **"a full working
day in nocx with herdr stopped" is now 0.7's criterion**, and the leaves that were still
open came with it. If you have been waiting to uninstall herdr, wait for 0.7.

Stop now does what it says on every local pane. A Stop pressed while a command was still
starting used to be signalled at whatever the shell had in front instead of at your command;
it is now held for the command's own start. And a command that ignores the first interrupt
now actually receives the next one, rather than being reported as stopped while it runs.

## Install

macOS, through the project's own Homebrew tap:

```bash
brew install --cask shady2k/nocx/nocx
```

The cask clears macOS quarantine for the installed app. That is an explicit trust decision:
you trust the tap and accept that it removes the quarantine attribute — read the
[tap README](https://github.com/shady2k/homebrew-nocx) first. The app is ad-hoc signed and
not notarized. A direct download from [GitHub Releases](https://github.com/shady2k/nocx/releases)
still needs the one manual step described in the [README](../../README.md#install-macos).

Linux, x86_64:

```bash
curl -fsSL https://nocx.dev/install.sh | sh
```

The installer verifies the signed release manifest before it puts the AppImage anywhere, so
a tampered download fails rather than installs. OpenSSL 3 or newer is required.

## Also in this release

- **A recovery card that keeps up.** When a pane is reclaimed after the recording hit its
  size limit, the card now tracks what is missing as more is dropped, instead of freezing
  the number it was built with.
- **A coordinator that hears its workers on time.** A queued wake is no longer blocked by a
  line the coordinator could not submit, and Claude's grey prompt suggestion is read as a
  suggestion rather than as typing.
- **Fewer wrong-column edges.** The grid no longer takes a width the scroller then clips, so
  the last column stays whole while a command runs — the same number of columns in Chromium
  and WebKit.

Everything 0.4 had is still here: the local terminal, the SSH manager, workspaces, session
restore, the sidebar (Files, Git, Ports, Notes, Operations), encrypted command history, the
vault, snippets, file transfer, the API client, and the assistant that acts in the same
scrollback. For installation limits and recovery steps see the [README](../../README.md).

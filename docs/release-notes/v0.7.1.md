# nocx 0.7.1

0.7.0 left some zsh setups with a terminal that never finished a command, could not start
an agent the pane itself could find, and let a full-screen program's block show rows that
were not its own. This patch fixes those, and two smaller things you may have met: a
doubled first character after a keyboard-layout switch, and a notice that piled up instead
of leaving.

## Your shell integrates again

If your `.zshrc` was written by an earlier nocx, it still sources nocx's shell
integration — and since 0.6.1 that happened twice, which left the shell connected but
inactive: a command's block stayed Running with no way out, and no command ever finished.
The integration now establishes its channel once, whichever order the two loads happen in.

You no longer need to remove the nocx line from your shell startup file.

## `claude` starts, even when nocx cannot orchestrate it

A pane that could not be orchestrated used to refuse to start your agent at all. It now runs
the real `claude` and still tells you the pane is unorchestrated, so the agent works and you
know what is missing.

## An agent starts even when the app cannot see it

Starting `claude` failed with "the local agent executable could not be resolved"
when nocx could not find it — an app opened from Finder sees a much smaller `PATH`
than your shell does. nocx now asks the pane where the program is, and starts that.

Putting a full path into the agent record is no longer necessary.

## A full-screen program's block shows its own output

Over ssh, the block for a full-screen program such as `htop` could complete
showing earlier commands' rows — a previous listing, or the screen of a TUI that
had already exited. The block now ends where the program's own output ends.

## A burst of lost output is one notice, not a wall of cards

When live output is lost, nocx used to stack a card per event and keep them. It now shows one
bounded notice with a running total, and the notice leaves on its own instead of pushing the
terminal away.

## Switching the keyboard layout no longer doubles the next character

After switching the macOS input source, the first character you typed could arrive
twice — `claude` came out `cclaude`. It arrives once now, and chords such as Cmd+C and
Control+C keep working.

## What 0.7.1 does not include

Signed nightly builds remain in 0.8.
